The community plugin index publishes on the family's aligned version 0.4.18, on the same version as the dsh-web family's 0.4.18. This release carries no user-visible feature change: since `v0.4.17` the repository holds exactly one commit, moving the `@deepseek-ai` SDK cohort from `0.2.2-rc.1` to `0.2.2-rc.2`. `community.json` is untouched and the catalog stays at 124 entries, with the package name, the entry data structure, the install path and the wire protocol all unchanged.

> **Compatibility**: the host floor moves up with the cohort — `dsh.engines.dsh` and the `@deepseek-ai/dsh` peer go from `>=0.2.2-rc.1` to `>=0.2.2-rc.2`, the only admission change in this release; a host on `0.2.2-rc.1` no longer satisfies that floor. Beyond it there are no breaking changes: the package name `@linxin666/dsh-client-ui-community-plugins`; the install path (the same package name from the registry, with the same `files` list and `exports` entry points); the persistence identifiers (`community.json`'s filename, entry shape and field names, plus the already-persisted `ui-community-plugins` mount row and the related profile keys); and the wire protocol (the inert `ui-community-plugins` row of the bundle patch and the fields the plugin exposes to the host) are neither renamed nor reshaped.

### New Features

This release adds no feature, and nothing is registered or retired.

### Other Changes

- Adopt the SDK cohort the family's 0.4.18 requires (5e80668): the 11 `@deepseek-ai/dsh-*` devDependency ranges, the `dsh.engines.dsh` floor and the `@deepseek-ai/dsh` peer all move from `0.2.2-rc.1` to `0.2.2-rc.2`, while Cordis stays at `^4.1.0`
